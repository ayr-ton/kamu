# Assets & Tailwind CSS

## Overview

Static assets consist of:
- **CSS**: Generated by Tailwind CSS v4 standalone CLI
- **JavaScript**: Vendored HTMX and petite-vue (no build step)
- **Images**: SVG logos, favicon
- **No webpack, no npm, no Node.js**

## Directory Structure

```
static/
├── css/
│   ├── input.css       # Tailwind v4 source + config (checked in)
│   └── output.css      # Tailwind compiled output (gitignored)
├── vendor/
│   ├── htmx.min.js     # HTMX library (~14kb gzipped)
│   └── petite-vue.es.js # petite-vue library (~6kb gzipped)
└── images/
    ├── logo.svg
    ├── logo-dark.svg
    └── favicon.ico
```

## Tailwind CSS Setup

### Standalone CLI (Containerized)

The Tailwind CSS v4 standalone CLI runs inside a container — no local binary
download needed. The `Containerfile` defines two stages:

- **`tailwind`** — Debian slim image with the CLI binary installed. Used for
  dev builds via `make tailwind-build` / `make tailwind-watch`.
- **`build-tailwind`** — Extends `tailwind`, copies templates, and produces
  the minified `output.css`. Used during `podman build` for production images.

The container image is built once and cached by Podman. Subsequent runs
resolve from cache in seconds.

### Configuration (CSS-First, No JS Config)

Tailwind v4 uses CSS-first configuration. All settings live in
`static/css/input.css` — no `tailwind.config.js` is needed.

Key directives:
- `@import "tailwindcss"` — replaces the old `@tailwind base/components/utilities`
- `@source` — tells Tailwind which directories to scan for class usage
- `@custom-variant` — configures class-based dark mode
- `@theme` — defines custom design tokens (colors, fonts)
- `@utility` — defines reusable component classes

### Source File (`static/css/input.css`)

```css
@import "tailwindcss";

@source "../../core/templates/";
@source "../../books/templates/";
@source "../../waitlist/templates/";

@custom-variant dark (&:where(.dark, .dark *));

@theme {
  --color-primary-50: #eff6ff;
  --color-primary-500: #3b82f6;
  --color-primary-600: #2563eb;
  --color-primary-700: #1d4ed8;
  --color-primary-900: #1e3a5f;
  --font-sans: "Open Sans", system-ui, sans-serif;
}

@utility btn { ... }
@utility btn-primary { ... }
@utility btn-secondary { ... }
@utility btn-danger { ... }
@utility card { ... }
```

### Build Commands

```bash
# Development: watch mode (auto-rebuild on template changes)
make tailwind-watch

# Production: minified build
make tailwind-build
```

## Vendoring JavaScript Libraries

HTMX and petite-vue are downloaded once and checked into the repository:

```bash
# HTMX
curl -sL https://unpkg.com/htmx.org@2/dist/htmx.min.js -o static/vendor/htmx.min.js

# petite-vue
curl -sL https://unpkg.com/petite-vue@0.4.1/dist/petite-vue.es.js -o static/vendor/petite-vue.es.js
```

These files are committed to the repository so there's no external dependency
at build or deploy time.

## WhiteNoise Configuration

Django serves static files via WhiteNoise in all environments:

```python
STATICFILES_DIRS = [
    os.path.join(BASE_DIR, "static"),
]
STATIC_URL = "/static/"
STATIC_ROOT = os.path.join(BASE_DIR, "staticfiles")

MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware",
    # ...
]

STORAGES = {
    "staticfiles": {
        "BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage",
    },
}
```

## CSS Migration Strategy

Each React component's CSS needs to be replaced with Tailwind utilities
applied directly in Django templates. This is done page-by-page during
Phase 2 of the migration.

### Migration mapping

| React Component + CSS      | Django Template                          |
|---------------------------|------------------------------------------|
| App.css                   | `base.html` (layout, background, fonts)  |
| Header.css                | `navbar.html` (navigation bar)           |
| LibrarySelector.css       | `books/library_list.html`                |
| Book.css                  | `books/partials/book_card.html`          |
| BookList.css              | `books/book_list.html`                   |
| BookDetail.css            | `books/book_detail.html`                 |
| SearchBar.css             | Search input in `books/book_list.html`   |
| MyBooks.css               | `books/my_books.html`                    |
| WaitlistIndicator.css     | `books/partials/book_action.html`        |
| ErrorMessage.css          | Error states in templates                |
| ErrorBoundary.css         | (removed — server errors handled by Django) |

### Approach

1. Read the existing CSS file to understand the visual design
2. Translate CSS properties to Tailwind utility classes
3. Apply classes directly on HTML elements in templates
4. Verify visual parity during manual testing
5. Delete the old CSS file after verification

## Optimization (Production)

- Tailwind CSS `--minify` flag removes unused classes and minifies output
- WhiteNoise `CompressedManifestStaticFilesStorage` adds gzip compression
  and cache-busting hashes
- HTMX and petite-vue are already minified
- Total frontend JS payload: ~20kb gzipped (vs ~250kb+ with React + Material-UI)
